# 小爱音量设置 1.3.0 验证报告

验证日期：2026-09-16

## 改动目的

1.2.1 需要按小爱版本映射混淆流选择类：平板 7.13.33 使用 `k00.o`，手机 7.13.21 使用 `d00.o`。1.3.0 删除这两处映射，把“使用媒体音量”的核心实现移到 Android 框架 API：

- `AudioManager`：在小爱进程中，把流 11 的音量读取改为流 3。
- `AudioTrack`：把助手流或 `USAGE_ASSISTANT` 播放改为媒体流 / `USAGE_MEDIA`。
- `MediaPlayer`：把助手流或助手用途改为媒体流 / 媒体用途。
- 小米私有的媒体静音、最低音量和自动调整方法按完整签名逐项探测，缺失时跳过该保护，不会关闭框架重定向。

模块自己的同步器通过线程内旁路读取真实的流 11 档位，防止框架重定向造成递归或错误换算。

## 实机

- 设备：小米 23116PN5BC / shennong
- 系统：HyperOS OS3.0.306.0.WNBCNXM
- Android：16 / API 36
- 小爱同学：7.13.21.0017 / 507013021
- LSPosed：作用域包含 `com.miui.voiceassist` 与 `android`
- 测试设置：同步关、使用媒体音量开、前台按键转发关

## 结果

诊断构建在小爱主进程、`:core` 和 `:voice_trigger` 中加载成功：

```text
DIRECT_MEDIA_HOOKS_READY 1.3.0 frameworkReads=6 privateGuards=7 hooks=21
```

诊断广播结果：

```json
{"assistantReadsMedia":true,"internalMuteBlocked":true,"volumeFloorBlocked":true,"playbackStarted":true,"playbackUsesMedia":true,"mediaIndexUnchanged":true,"media":8}
```

用 `android.intent.action.ASSIST` 启动真实小爱 `VoiceService` 后，模块与 AudioService 都记录到媒体播放：

```text
PLAYBACK AudioTrack stream=3 usage=1
package:com.miui.voiceassist type:android.media.AudioTrack
attr:AudioAttributes: usage=USAGE_MEDIA
```

临时打开“同步”并保持“使用媒体音量”开启时，媒体真实保存档位 8 / 29 映射为助手 4 / 15，证明同步器能绕过重定向读取并写入独立助手流。测试后恢复用户原设置：同步关、使用媒体音量开、前台按键转发关。

构建阶段的音量换算边界、单调性、非零最小档与前台按键路由测试通过；APK 通过 v3 签名和 ZIP 对齐检查。

## 正式版重启验证

安装 1.3.0 正式版并完整重启后，LSPosed 的系统进程日志为：

```text
XiaoAiVolumeSync SYSTEM_KEY_ROUTER_READY 1.3.0
```

解锁后强制停止并重新启动小爱，主进程、`:core` 和 `:voice_trigger` 均加载 1.3.0。模块页面确认：同步关、使用媒体音量开、前台按键转发关，播放选择为流 3，系统按键路由版本为 1.3.0。正式版发送诊断广播返回 `result=0`，确认诊断接收器没有进入发布包。

通过小爱的语音触发入口打开 `voice_assist_root` 浮窗，真实播放日志为：

```text
PLAYBACK AudioTrack stream=3 usage=1
```

浮窗前台期间发送一次音量加键：媒体流由 8 / 29 变为 9 / 29，助手流保持 4 / 15；发送音量减键后媒体恢复为 8 / 29。该结果验证“使用媒体音量”开启时，即使“前台按键转发”关闭，活动播放器也会让音量键直接调整媒体流，不会再改助手流后被同步拉回。

## 兼容边界

Android 框架 Hook 点比小爱混淆类稳定，常规小爱升级不再需要新增 `k00.o` / `d00.o` 映射。小米仍可能改写私有的静音或自动音量代码；升级小爱后应检查模块状态页中的最近 AudioTrack 是否为流 3 / 用途 1，并实际听一次播报。私有保护方法缺失时，核心媒体读取与播放重定向仍会启用。
