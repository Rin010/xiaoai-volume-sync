# 小爱音量设置 1.4.0 验证报告

验证日期：2026-09-16

## 功能

新增“禁用小爱同学静音媒体音量”开关，默认开启。它独立于同步、使用媒体音量和前台按键三个开关：

- 开启：拦截小爱的 `setMusicStreamMute`、`setMusicStreamUnMute` 和 `checkMute`。
- 关闭：上述方法按小爱原始逻辑执行。
- 切换通过现有设置广播即时下发到小爱各进程，不需要重启小爱。

已有的媒体播放重定向与自动抬高音量保护仍由“使用媒体音量”控制。

## 诊断构建实测

设备：小米 23116PN5BC / shennong，HyperOS OS3.0.306.0.WNBCNXM，Android 16，小爱 7.13.21.0017。

1.4.0 在小爱主进程、`:core` 和 `:voice_trigger` 中成功加载，三个进程均读取到新增开关：

```text
OPTIONS sync=false direct=false frontKeys=false blockMediaMute=true
DIRECT_MEDIA_HOOKS_READY 1.4.0 frameworkReads=6 privateGuards=7 hooks=21
```

为复用静音播放诊断，测试期间临时打开“使用媒体音量”。静音拦截开启时：

```json
{"muteGuardEnabled":true,"internalMuteBlocked":true,"playbackUsesMedia":true,"mediaIndexUnchanged":true,"media":9}
```

关闭静音拦截后立即重复测试：

```json
{"muteGuardEnabled":false,"internalMuteBlocked":false,"playbackUsesMedia":true,"mediaIndexUnchanged":true,"media":9}
```

第二次测试中，小爱的原始媒体静音调用真实执行，诊断代码随后调用其恢复方法，将媒体还原到测试前状态。媒体保存档位始终为 9 / 29，测试结束后恢复用户原设置：同步关、使用媒体音量关、前台按键转发关、媒体静音拦截开。

构建阶段的音量换算与按键路由测试通过；诊断 APK 通过 v3 签名和 ZIP 对齐检查。

## 正式版重启验证

安装正式版并完整重启后，系统进程确认加载 1.4.0：

```text
XiaoAiVolumeSync SYSTEM_KEY_ROUTER_READY 1.4.0
```

首次解锁后重新启动小爱，主进程、`:core` 和随后启动的 `:voice_trigger` 均读取：

```text
OPTIONS sync=false direct=false frontKeys=false blockMediaMute=true
```

模块页面实时显示“禁用媒体静音实际值：开”和系统路由 1.4.0。正式版中关闭、重新开启该开关后，三个小爱进程分别即时记录 `blockMediaMute=false` 与 `blockMediaMute=true`；最终恢复为开启，媒体保持 9 / 29。发送诊断广播返回 `result=0`，确认发布包没有注册诊断接收器。
